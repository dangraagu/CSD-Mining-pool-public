## P1 — auto-detect reliability (the v0.1.19 gap a real rig hit)

A HiveOS NVIDIA rig with `--address` only (no `--backend`) fell back to the **CPU
seed and mined nothing** — `cuda=false opencl=false`, `backend=auto … SELECTED cpu …
cpu mining disabled; GPU-only`, `got_job` but 0 H/s. The same rig with explicit
`--backend cuda` (and via a different config) mined fine on NVIDIA. So
`detect_variant` in `hiveos/h-run.sh` is **inconsistent at launch** — it can return
`cpu` while the GPU is present (probe timing: `nvidia-smi`/driver not ready when
h-run runs at boot), so no GPU variant is fetched and the rig silently runs the cpu
seed in GPU-only mode = mines nothing (the worst outcome — "online but 0 H/s").

Fix candidates (pick the robust set):
1. **Loud fail-safe:** when the resolved variant is the cpu seed AND no `--backend`
   was given AND the binary then finds no usable GPU → emit a LOUD warning to the
   miner log AND actually **CPU-mine** (don't sit in GPU-only mode doing nothing).
   Mining-something beats mining-nothing.
2. **Retry detect_variant:** re-run the GPU probe after a short delay / on the next
   sidecar poll so a not-yet-ready driver self-corrects without an operator re-apply.
   Bound it (timeout-guarded, brick-safe — already the pattern).
3. **Docs already updated (no release needed):** `docs/HIVEOS.md` now recommends
   setting `--backend` explicitly on HiveOS and warns that omitting it can fall to
   the CPU build. Keep that.

Regression test: simulate `detect_variant` returning cpu on a GPU box at first call
(stub nvidia-smi to fail once then succeed) → assert the retry resolves nvidia OR the
fail-safe cpu-mines + warns. Must reproduce the "mines nothing" state on old code.

## P2 — suggest-difficulty CPU over-report (~10×)

The startup benchmark over-reports ~10× on the CPU-fallback path → a new CPU rig
seeds vardiff too high and submits no shares until it corrects. Errs SAFE (no flood)
but is the wrong magnitude for the rig that most needs a sane starting diff. ~1-line
calibration on the CPU path.

## P3 — lower-priority (from the latent-issue hunt)

- Miner default `--cpu-threads 16` / `--cpu-share 0.4` spins a 16-thread CPU pool on
  every GPU rig for ~0.1% more hashrate (×N on multi-GPU h-run). Default to 0 /
  opt-in dual-mining.
- HiveOS/standalone-bundled `csd-relay-node` on consumer rigs: no prune, unbounded
  `--datadir` + `relay.log` on small SSD/USB. Bound `relay.log`; add a free-space
  preflight in `h-run.sh`/`mine-auto.sh`.
